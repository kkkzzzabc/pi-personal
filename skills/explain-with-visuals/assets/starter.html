Mechanism · illustrative teaching model

Why can a saved result avoid repeated work?

A valid saved result lets a request reuse earlier work instead of computing the same result again.

The avoided work is the point

A hit means the needed valid result is already available; a miss means it is not. Reuse can skip the original computation, but finding and validating a saved result still has a cost.

Limitation: lookup is not always cheaper than computation. Changed inputs may make a saved result invalid; real systems need a validity or invalidation policy.

Counts do not measure speed

In a synthetic set of 10 requests, 7 hits and 3 misses describe how often each path was taken, not how fast it ran.

Evidence and verification

This is an intentionally simplified teaching example, not a diagram of a particular implementation. The supplied synthetic counts sum to 10; labels and paths describe the model above.
